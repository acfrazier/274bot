# 0.1.8.1 → 0.1.9 upgrade compatibility

This is the release audit for upgrading a real 0.1.8.1 installation in place.
The rule is that every file a 0.1.8.1 user can have on disk must remain usable
without loss. The release gate below is mandatory on each packaged platform.

## Audited revisions and method

- 0.1.8.1: annotated tag peeled to host commit
  `a88d077644dadbda21546f702d9717d808004a74`; client commit
  `c539f24315775c71a2b8c79935ae86b155f446fd`.
- 0.1.9 campaign: `76e9bb2450a4061d85f640cdc1a1887a053488ec`.
- Merged frontend-core vault orchestration:
  `c510ef2392b0c00a9532c3425c9d6deca474d711`.
- Current client: `2ec306496cb27e327036aceb138face383ce222b`.
- Upgrade audit/fixture/test: `decee70a653601c3d390a7f3c475f41f8bff3a1b`.
- Older-external-pack compatibility fix:
  `d931857cb7e91ab7f7f544899f9430416d630bf5`.

The audit compared the old/current readers and writers, enumerated literal
`~/.274bot` paths in panel, TUI, host, script, nav, and client-cache code, and
checked the published 0.1.8.1 source/build receipt. Gate step 0 records the
repeatable source audit and exact file list; it must be rerun against the
release-candidate commit. The permanent test uses files generated by the exact
old code; see
[`crates/panel/tests/fixtures/upgrade-0.1.8.1-home/README.md`](../crates/panel/tests/fixtures/upgrade-0.1.8.1-home/README.md).

packaging data, not operator-authored state.

## New 0.1.9 artifacts

These cannot conflict with a stock 0.1.8.1 home because that release did not
create them:

- `instance.lock` and `instance.holder`: process-lifetime advisory lock and
  plain `panel|tui PID` marker. They protect concurrent writers and are removed
  or released on drop/process exit; they do not contain settings.
- `map-cache/<revision>/{catalogue,images}/<identity-key>/…`: generated,
  schema-checked map catalogue/image data. Keys bind revision, selected client
  content, nav service data, and producer policy, so stale data misses and is
  rebuilt rather than being mistaken for current data.
- `<snapshot-version>/ondemand/…` and bundled `274bot.navpois`: derived cache
  additions described above.

## Permanent regression test

Run:

```text
cargo test -p panel --test upgrade_compat_0181
```

The test must remain a consumer-behavior test. It must not recreate the fixture
with current structs, compare source text, or merely check that deserialization
did not throw. When a persisted meaning is added to an existing wire type, add
a non-default old fixture value where possible and assert both initial read and
current save/reopen behavior. Never regenerate the committed fixture with
current code.

## Packaged release gate

For each macOS arm64, Windows x64, and Linux x64 release package:

0. Re-run the persisted-wire/source-path audit against the exact RC commit.
   Save all three outputs with the package evidence; inspect every diff rather
   than treating an empty grep as proof.

   ```bash
   BASE=a88d077644dadbda21546f702d9717d808004a74
   OLD_CLIENT=c539f24315775c71a2b8c79935ae86b155f446fd
   RC=$(git rev-parse HEAD)
   CLIENT_RC=$(git -C vendor/fr-client-rust rev-parse HEAD)
   persisted=(
     crates/vault/src/lib.rs
     crates/frontend-core/src/session_tests.rs
     crates/frontend-core/tests/fixtures/vault-0.1.8.1.bin
     crates/panel/src/ui_state.rs
     crates/panel/src/nav_settings.rs
     crates/panel/src/theme.rs
     crates/script/src/loadouts_store.rs
     crates/script/src/settings_store.rs
     crates/script/src/identity.rs
     crates/script/src/load/library.rs
     crates/script/src/js_cache.rs
     crates/script/src/rs2b0t_registry.rs
     crates/script/src/rs2b0t_registry
     crates/host-play/src/public_worlds.rs
     crates/host-play/src/profile.rs
     crates/host-play/src/profile_options.rs
     crates/host-play/src/profile_selection.rs
     crates/host-play/src/profile_binding.rs
     crates/nav/src/pack.rs
     crates/nav/src/manifest.rs
     crates/nav/src/bundle.rs
   )
   mkdir -p gate-audit
   printf 'host old=%s\nhost rc=%s\nclient old=%s\nclient rc=%s\n' \
     "$BASE" "$RC" "$OLD_CLIENT" "$CLIENT_RC" |
     tee gate-audit/revisions.txt
   git diff --find-renames --unified=80 "$BASE" "$RC" -- "${persisted[@]}" \
     > gate-audit/host-persistence.diff
   for rev in "$BASE" "$RC"; do
     printf '\n===== %s =====\n' "$rev"
     git grep -n -E \
       'serde|Serialize|Deserialize|[.]274bot|vault|panel-ui|loadouts|script-settings|worlds[.]json|js-scripts|js-cache|rs2b0t|navpack|unpack' \
       "$rev" -- crates vendor/fr-client-rust
   done > gate-audit/persisted-paths.txt
   git -C vendor/fr-client-rust diff --find-renames --unified=80 \
     "$OLD_CLIENT" "$CLIENT_RC" -- crates/client/src/unpack \
     > gate-audit/client-unpack.diff
   ```

   Refresh the 0.1.9 candidate and current-client pins at the top of this
   document to the recorded, reachable RC commits. Any added field, default,
   path, rename, delete, format byte, migration, or `deny_unknown_fields` is
   unresolved until covered by an old-file behavioral proof and an audit-table
   entry.
1. Start from a fresh scratch OS account/home. Never point a gate run at an
   operator home or real vault.
2. Install and launch the published 0.1.8.1 package once. Populate/copy the
   committed 0.1.8.1 fixture into that scratch home, preserving filenames and
   using passphrase `bot`.
3. Capture hashes and a recursive filename list of the scratch `.274bot`
   directory. Keep a protected copy for comparison.
4. Replace only the installed application/package with the candidate 0.1.9
   package. Do not pre-migrate, rename, or delete home files.
5. Use the local-289 engine on game `127.0.0.1:44594` and asset
   `127.0.0.1:1080`. `MATCHING_ENGINE/data/pack/client` and its content tree
   must be the exact inputs recorded by the RC nav bake, so their cache/content
   identities match the bundle row compiled into the package. Do not stage a
   nav pack into the scratch home and unset `NAV_PACK`/`NAV_FLAGS`. Launch the
   installed package executable, not a Cargo binary:

   ```bash
   env -u NAV_PACK -u NAV_FLAGS ENGINE_DIR="$MATCHING_ENGINE" \
     "$PACKAGE_EXE" --profile local-289 \
     --engine "$MATCHING_ENGINE" \
     --cache "$MATCHING_ENGINE/data/pack/client" \
     --host 127.0.0.1 --port 44594 \
     --asset-host 127.0.0.1 --http-port 1080 \
     2>candidate-stderr.log
   ```

   On macOS, `PACKAGE_EXE` is the executable under the installed `.app`'s
   `Contents/MacOS`; on Linux it is the installed `panel-play`. On Windows,
   remove `NAV_PACK` and `NAV_FLAGS` from the process environment and pass the
   same arguments to the installed `panel-play.exe` from PowerShell. The VM
   harness port forwards must be active before launch.
6. Unlock with `bot`; verify all three profiles appear, the last-focused
   profile and represented panel/nav/theme prefs appear, both loadouts and
   ChickenKiller overrides appear, and `fixture-auto` reaches a logged-in game
   state. Save one preference and one profile setting, exit cleanly, relaunch,
   and verify both persisted.
7. Prove the nav source from the captured stderr line
   `host-play: navigation source: packaged 274V10 bundle: <path>`. The path
   must be inside the installed package resources; inspect its first five bytes
   as `274V` plus byte 10 and verify sibling `274bot.navpois` exists. Opening
   WalkTo must show the map or an explicit cache-building state. Then make
   separate launches with `--nav-pack` pointing at protected old V8 and V9
   files. Each startup must continue, stderr must contain
   `navigation pack was built by an older 274bot; rebuild it with nav-pack`,
   navigation must be unavailable, and each old file's hash must not change.
8. Compare the protected copy with the post-run home. Expected changes are
   encrypted vault/prefs bytes after the deliberate save, generated caches,
   current-run log, and transient/new lock files. Profile count, credentials,
   uids, settings, assignments, loadouts, script overrides, JS registrations,
   imported-catalog markers, world endpoints, and referenced source files must
   be semantically identical.
9. Archive the source-audit output, VM harness stdout/stderr, and screenshots
   showing unlock, profiles/settings, loadouts/overrides, successful login,
   packaged nav origin, old-V8/V9 degradation, and relaunch. Record package
   digest, OS image, candidate host/client commits, and expected file deltas.
10. Stop/delete the scratch guest or account. A missing package, failed unlock,
    reset-to-default old state, dropped item/setting, a non-V10 packaged nav
    resource, an older external pack aborting startup, or inability to log in
    is a release blocker.
