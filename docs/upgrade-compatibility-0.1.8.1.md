# 0.1.8.1 → 0.1.9 upgrade compatibility

This is the release audit for upgrading a real 0.1.8.1 installation in place.
The rule is that every file a 0.1.8.1 user can have on disk must remain usable
without loss. The release gate below is mandatory on each packaged platform.

## Audited revisions and method

- 0.1.8.1: annotated tag peeled to host commit
  `a88d077644dadbda21546f702d9717d808004a74`; client commit
  `c539f24315775c71a2b8c79935ae86b155f446fd`.
- 0.1.9 campaign: `92df32ce2ebde836946c9158c9ccce1c186a3413`.
- In-flight frontend-core branch, included because it changes vault write
  orchestration: `8ce2c5e7a808628957191e2412318589c19b08d5`.

The audit compared the old/current readers and writers, enumerated literal
`~/.274bot` paths in panel, TUI, host, script, nav, and client-cache code, and
checked the published 0.1.8.1 source/build receipt. The permanent test uses
files generated by the exact old code; see
[`crates/panel/tests/fixtures/upgrade-0.1.8.1-home/README.md`](../crates/panel/tests/fixtures/upgrade-0.1.8.1-home/README.md).

## New 0.1.9 artifacts

These cannot conflict with a stock 0.1.8.1 home because that release did not
create them:

- `instance.lock` and `instance.holder`: process-lifetime advisory lock and
  plain `panel|tui PID` marker. They protect concurrent writers and are removed
  or released on drop/process exit; they do not contain settings.
- `map-cache/<revision>/{catalogue,images}/<identity-key>/…`: generated,
  schema-checked map catalogue/image data. Keys bind revision, selected client
  content, nav service data, and producer policy, so stale data misses and is
  rebuilt rather than being mistaken for current data.
- `<snapshot-version>/ondemand/…` and bundled `274bot.navpois`: derived cache
  additions described above.

## Permanent regression test

Run:

```text
cargo test -p panel --test upgrade_compat_0181
```

The test must remain a consumer-behavior test. It must not recreate the fixture
with current structs, compare source text, or merely check that deserialization
did not throw. When a persisted meaning is added to an existing wire type, add
a non-default old fixture value where possible and assert both initial read and
current save/reopen behavior. Never regenerate the committed fixture with
current code.

## Packaged release gate

For each macOS arm64, Windows x64, and Linux x64 release package:

1. Start from a fresh scratch OS account/home. Never point a gate run at an
   operator home or real vault.
2. Install and launch the published 0.1.8.1 package once. Populate/copy the
   committed 0.1.8.1 fixture into that scratch home, preserving filenames and
   using passphrase `bot`.
3. Capture hashes and a recursive filename list of the scratch `.274bot`
   directory. Keep a protected copy for comparison.
4. Replace only the installed application/package with the candidate 0.1.9
   package. Do not pre-migrate, rename, or delete home files.
5. Launch 0.1.9 against the local test engine. Unlock with `bot`; verify all
   three profiles appear, the last-focused profile and panel/nav/theme prefs
   appear, both loadouts and ChickenKiller overrides appear, and the
   `fixture-auto` profile reaches a logged-in game state. Save one preference
   and one profile setting, exit cleanly, relaunch, and verify both persisted.
6. Verify the candidate loaded its packaged V10 nav bundle (and `navpois`) rather
   than trying to use an old V9 package resource. Opening WalkTo must either
   show the map or an explicit cache-building state, never delete operator
   state.
7. Compare the protected copy with the post-run home. Expected changes are
   encrypted vault/prefs bytes after the deliberate save, generated caches,
   current-run log, and transient/new lock files. Profile count, credentials,
   uids, settings, assignments, loadouts, script overrides, JS registrations,
   imported-catalog markers, world endpoints, and referenced source files must
   be semantically identical.
8. Archive the VM harness stdout/stderr and screenshots showing unlock,
   profiles/settings, loadouts/overrides, successful login, and relaunch. Record
   package digest, OS image, candidate commit, and any expected file deltas.
9. Stop/delete the scratch guest or account. A missing package, failed unlock,
   reset-to-default old state, dropped item/setting, V9 packaged nav resource,
   or inability to log in is a release blocker.
