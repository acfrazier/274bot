# Inventory useOn identity preservation

The compatibility shim now carries the exact inventory identity selected by a script through `useOn`: source object id + slot for every target kind, and target object id + slot when the target is another inventory handle. Inventory snapshot rows publish their real container slot alongside the existing object id. These are optional additions to the internal shim shape and FlatBuffer tables, so old name-only requests and old buffers remain readable.

Rust dispatch treats an id/slot pair as one identity. Both values must be present and match one current `GameSnapshot::inventory()` row; a missing item, moved item, replaced slot, or partial pair sends nothing. Once resolved, dispatch still calls `Interactions::use_item_on`, retaining its inventory-container and `still_present` checks and the existing two-packet game behavior. When no identity pair is supplied, source and inventory target resolution keeps the previous first-name-match behavior. Scene targets and `UseWidgetOn` retain their existing resolution.

Focused coverage proves the full shim value-bridge and FlatBuffer round trip with same-name inventory rows, exact non-contiguous source/target slots, a scene-target call with an exact source identity, and a legacy name-only firemaking call. Host dispatch coverage proves exact source and target selection despite earlier same-name rows, rejects stale and partial identities without a packet, and retains legacy first-name matching. This task does not change the client/game protocol, catalog sources, scenario harnesses, timing, completion semantics, or LIVE evidence.
