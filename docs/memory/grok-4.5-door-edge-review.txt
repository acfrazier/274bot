### What changed (behavior)

`door_far_side` no longer walks outward until the first standable tile. It only accepts the **immediate neighbor** in `dir` if `WorldCollision::standable` is true.

That correctly kills the bank-return bug: Door1530 at `(2656,3292)` used to walk west over blocked counter/plant/bench tiles and land at `(2651,3292)`. Captured flags in the new unit test confirm west neighbor `(2655,3292)` is `WALK_SCENERY`-blocked (`0x4120`), while `(2651,3292)` is standable face-only (`0x4020`) — old walk-out would “succeed,” new logic returns `None`.

Webs are split to `web_far_side` and keep the old multi-tile walk-out. Call sites:

- `door_edges` (shape-0 doors + `gates.loc` fence gates) → adjacent-only
- `toll_edges` (Al Kharid border gates) → adjacent-only via same helper
- `web_edges` → unchanged walk-out

Router still takes door edges from any standable tile within interact radius of `at` and lands on `to`; requiring `to` adjacent+standable matches one-tile wall-door crossings and does not invent a path through scenery.

### Boundary / border gates / valid doors

- **OOB neighbor:** `standable` is false off-grid → no edge (same practical outcome as old OOB exit).
- **Blocked neighbor:** no edge (intended).
- **Face-flag-only neighbor:** still standable → edge kept (Catherby wall-980 south landing still valid under existing tests).
- **Border toll gates:** same shape-0 path; open-road adjacent landings should still emit both dirs. Existing real-content test still demands two edges per 2882/2883 — good canary if content is present.
- **Fence gates:** same helper; one-tile cross is correct.
- **Webs:** explicitly preserved; not treated as wall doors.

No functional defect found in the new boundary rule for shape-0 wall doors/gates.
