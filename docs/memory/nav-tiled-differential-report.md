## Actual source independence

`harness.py materialize` reads named Git blobs, verifies Git blob SHA-1 and
records SHA-256/length, and materializes only complete nav, api and client crate
inputs. Dense has 209 original files / 4,457,777 bytes; tiled has 210 /
4,506,538. There is no second abbreviated router, and no comparison of two tiled
instances masquerading as old/new.

Original decoder, collision and transport implementation bytes are retained.
Original router bytes are retained as an exact prefix; its only addition is a
module declaration loading a small access bridge to its existing private
`find_bounded_impl`. That bridge forwards arguments and returns the complete
original result; it supplies no search algorithm. It permits bounded-budget and
walking-cost/all-option checks without rewriting original visibility or logic.

The binary root duplicates the original library module declarations and adds
`probe`. Three explicit storage adapters read original dense fields versus
candidate logical accessors: geometry/count, exact pair, and blocked words.
There is no baseline reference to tiled accessors or constructor.

For radius/bank orchestration, six exact source spans from the corresponding
frozen host-play lib are included: PendingBankFetch, RouteOutcome,
route_or_bank_fetch, approach_tiles, ScriptRouteRequest and its calculate impl.
The full source file and byte-span hashes are retained. No host/live client is
constructed. This tests the existing radius selection and fallback policy, not
an invented approximation of it.

Before build and before/after each arm, the harness checks original source bytes
and admitted full source-tree/executable hashes. `audit.py` additionally matched
every original source manifest oid to the exact named commit tree, matched the
host file against its commit, and checked all host spans. There was no source
movement while probes ran. Registry dependencies remain Cargo/lockfile-managed;
the harness does not provide a hermetic OS/SDK or vendored registry snapshot.

## Generated coverage and observed results

The enumerations below are both generated in code and checked against saved
complete output records. They are finite coverage, not a proof over all maps.

### Wire / graph / sidecars

- 868 prefixes: every byte truncation of the non-empty all-kind/all-requirement
  pack, covering all 25 header positions and every edge, requirement and bank
  section boundary/interior. Exact PackError Debug variants and string payloads
  come from each original decoder. No hand-written expected-error table.
- All 255 non-v8 version values; zero/oversize/u32-max dimensions, bad magic;
  every invalid transport tag 9..255, door direction 5..255 and bank access tag
  2..255. Bounded requirement count mutations, invalid quest and bank/NPC/dialog
  UTF-8, and accepted nonzero dialog-presence values 2 and 255 are included.
- Full ordered ordinary edges, teleports, every edge field, five requirement
  vectors, graph.at keys with their **original index-vector order**, and both
  booth and NPC bank access forms including optional dialog text.
- Interleaved teleports, duplicate at keys, noncanonical input edge ordering and
  trailing bytes. The audit verified that BOTH named noncanonical inputs really
  differ from baseline canonical encode; candidate output equals baseline
  canonical bytes, not an assumed input==encode identity.
- Flags sidecar: every prefix of the bounded sidecar including the full stream,
  partial trailing words, extra complete word and stale versions 0/2/255.
  Success outputs include the entire flags vector and canonical sidecar bytes.
- 79 legacy-grid prefixes including the full valid grid exercise the original
  `NavWorld::load_pack` BadMagic-only fallback and its actual second file read.
  Every non-corner pack fixture also exercises load_pack; v8 errors do not get

  are compared, not inferred from successful v8 decoding alone.

Observed records: 1,969 direct pack decode errors, 1,968 load errors, 136 sidecar
errors; 570 canonical/round-canonical pack pairs, 38 successful sidecar encodes.
All exact error payload frequencies are in `run-03/audit.json`.

Malformed fixture admission bounds valid decoder dimensions before decode and

an allocation guard, not the error oracle. It stops on invalid/truncated syntax
and lets original code decide errors. No enormous allocation bombs were run.
Arithmetic-overflow error paths cannot be reached on this 64-bit target after
both original parsers' 16,384-side checks; u32-max dimensions test the actual

## Bounds, future ONE-input mode, and still-open release

Generated probe limits per arm: 240s wall / 180s per-process CPU / 1-GiB sampled
process-group RSS / 512-MiB combined stdout+stderr and per-file size. Valid
fixture dimensions are capped at 65,536 cells, strings at 1 MiB, each file at
1 MiB, corpus at 15,000 inputs / 64 MiB. Actual inputs are far smaller. The
corpus-count cap was expanded explicitly from 10,000 to accommodate both-axis
corner enumeration; no probe resource cap was weakened.

Build limits: 600s wall / 480s per-process CPU / 6-GiB sampled group RSS /
8-MiB combined logs / 1-GiB artifact file cap; two Cargo jobs, no incremental.
Targets and locks are independent; builds and probe arms are serialized.

Future real limits are fixed in code: 900s wall / 800s per-process CPU /
1-GiB sampled group RSS / 4-GiB Linux address space / 4-GiB combined logs and
per-file output, one ≤128-MiB v8 input with ≤70,000,000 logical cells and
≤256 explicitly bounded frozen route rows. Real release requires an explicit
root authorization binding input hash/length, route hash, generated launch and
result, original sources, both executable/source admissions, unchanged limits,
and a hash-bound **same-platform successful Linux native-guard report**.
It copies one owned hash-verified input, preflights allocation bounds, then runs
arms separately. The complete cell/word/derived/wire/graph/banks stream and
frozen routes are compared directly. There is no default pack path.

Important limitations for root/reviewer:

- **Real input, native Linux guard qualification, native route-selector choice,
  real-pack §5.3, and Stage A/B remain OPEN.** This card grants no real-input or
  measurement release. Real positive authorization/supervisor path has not run
  on Linux here; only rejection on Darwin and the generated-byte executable
  protocol have been exercised.
- RSS is sampled group resident accounting, not an instantaneous hard peak.
  CPU and AS limits are per process. Cleanup owns the launched process group;
  this is not a sandbox against a hostile program intentionally escaping with
  setsid. Frozen probes are trusted single-process code; Cargo's normal children
  stay in the group. Native qualification must assess the intended environment.
- The fixed-selector protocol currently supplies the explicit small state/bank
  families documented above, not arbitrary live snapshot facts. Root must
  review whether its chosen real requirements/banks are meaningfully exercised;
  missing real facts cannot be described as successful requirement routes.
- No real-sidecar attachment is part of the one-pack mode. Generated sidecars
  cover decode and attach/drop/external queries; intentionally short accepted
  sidecar vectors are not attached where the old API would panic on access.
  Filesystem races, permission-error I/O and all possible malformed byte strings
  are not exhaustively represented.
- Original decode still overlaps input+dense collision+candidate conversion.
  The design's real-input construction model remains at least 150,792,821 bytes
  before graph/banks/allocator overhead. This diagnostic also retains a first
  world while encoding and decoding a roundtrip and may hold two wire buffers;
  it therefore has additional temporary owners. Root must admit this correctness
  harness's peak/output cap separately from a production startup measurement.
  A killed real arm is a failed proof, not permission to raise limits until green.
- Full results are large by design. At the admitted real upper cell limit, two
  15-byte-per-cell streams alone occupy 2,100,000,000 bytes, before blocked words,
  canonical wires, graph/banks and route output. Any cap breach must be retained.
- Probe receipt elapsed/RSS fields are guard diagnostics under overlapping
  developer activity, not clean native performance measurements or savings.
