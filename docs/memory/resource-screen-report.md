# Repeated clean resource screen

`resource_screen.analyze` consumes four explicit reference/candidate/candidate/reference receipts plus the independently re-read N16 overhead quartet. It invokes the existing artifact binder for every resource side; production has no callback or pre-bound-data API. All resource runs must have the hot profile group disabled, use the real TUI, and have counting/verbose/stack/failure/nav capture flags off.

The resource quartet requires independently qualified native/cache/process evidence, exact runtime/fixture/host settings, chronological nonoverlapping windows, four distinct run identities, stable binary bytes within each role, and matching server/ambient identities. The overhead candidate binary and sampler/cache/host/server configuration must match. The N16 overhead data informs the decision to disable profiles; it is not an extrapolated numerical overhead bound for a different N. Per-cell helper resources are measured anew and are not subtracted from host numbers.

The reader reports Rust host CPU and RSS independently from server and helper resources. Two repeated values per role yield observed ranges, not confidence intervals. CPU uses the reviewed 5% empirical range screen. RSS supports a reduction only when the minimum separation between the reference and candidate ranges exceeds the larger within-role spread. The two oriented candidate-minus-reference RSS deltas remain visible. No caller-supplied measured-overhead label grants a pass.

`candidate_resource_screen_supported` is a resource-only short-screen result. `accepted_rss_saving` and `final_acceptance` remain false. Longer confirmation, latency companion evidence, actual renderer backend evidence, absolute targets, lifecycle tests, reference deployment limits and whole-branch review remain explicit. Profile-off renderer rows do not identify the actual backend; only native draw/configuration and requested TUI policy are matched here. This module does not change or waive the existing full-pair/renderer acceptance gate.

Validation: 8 tests, including eight binding/flag/order/config counterexamples, helper-versus-host ownership, overlapping RSS variation, overhead-label rejection, callback rejection, non-object receipt rejection, and a real-artifact guard. The actual all-candidate overhead quartet cannot be relabeled as a reference/candidate comparison. No new control/candidate resource quartet has run yet.
